# UsbMemoryChecker

Проверка USB-флешек и карт памяти: скорость чтения/записи (100 МБ / 1 ГБ / 5 ГБ, средняя / макс / мин), реальный
объём (поиск поддельных «2 ТБ» флешек) и исправление — раздел на реальный объём. macOS (Apple Silicon) и Windows.
Отвечай пользователю по-русски. Описание для пользователя — [README.md](README.md) (английский) и
[README.ru.md](README.ru.md): меняешь одно — поправь второе. Комментарии в коде — по-английски (`update.rs`, `donations.rs`, `net.rs` взяты из 360Cleaner как есть, по-русски).

## Устройство

Rust (edition 2024) + tao 0.37 / wry 0.57 (системный WebView: WKWebView на Mac, WebView2 в Windows). Интерфейс —
`src/ui/index.html` (HTML/CSS/JS, `include_str!`), тексты — `src/ui/i18n.js` (Rust подставляет вместо `/*I18N*/`).
Окно 1180×760 (минимум 880×600) без прокрутки страницы: рейка дисков слева, справа полоса диска (карта ёмкости) и одна рабочая
карточка с вкладками (колонки «настройка» / «итог»; живой график полной проверки `#chartCap` показывается и на вкладке «Реальный объём»).
Прокручиваются только список дисков, таблица результатов и (в малых окнах) рабочая карточка. Проверка раскладки — `scripts/ui-check`.

- `main.rs` — окно, IPC, состояние (`State` под `Mutex`), одна задача за раз (`start_task`), наблюдатель дисков
  (`disk_watcher`, раз в 2 с / 4 с в Windows), донаты и обновления. `--helper <папка>` и `--cli …` — без окна.
- `disks.rs` — список съёмных носителей: macOS — `diskutil list/info -plist` (только не Internal / Removable /
  SD, без загрузочного), Windows — PowerShell `Get-Disk` (только USB/SD/MMC/1394, без IsBoot/IsSystem).
  `UMC_SHOW_VIRTUAL=1` показывает и образы дисков / RAM-диски (для проверки без флешки). У каждого носителя есть
  таблица разделов (`partitions`: смещение, размер, UUID тома; `table_id` — подпись MBR / GUID GPT в Windows); каждый
  вызов `diskutil` / PowerShell идёт через `net::output_timeout` (10 с / 30 с): зависший список или диск целиком
  проваливает опрос (прежний список остаётся), зависший `info` одного раздела лишь оставляет носитель без таблицы.
- `dio.rs` — прямой ввод-вывод мимо кэша: `F_NOCACHE` + `F_FULLFSYNC` на Mac, `FILE_FLAG_NO_BUFFERING |
  WRITE_THROUGH` в Windows (буферы, смещения и размеры кратны 4 КиБ — `AlignedBuf`).
- `pattern.rs` — тестовые данные: каждый блок 4 КиБ зависит от адреса и соли запуска.
- `bench.rs` — тест скорости (файл `.UsbMemoryChecker-speed.bin`, куски по 4 МиБ, окна по 16 МиБ для макс/мин).
- `pipe.rs` — заполнение данными и сверка на вспомогательном потоке (3 буфера по 4 МиБ, размер одного вызова), пока диск занят вводом-выводом.
- `fullcheck.rs` — полная проверка без стирания: папка `UsbMemoryChecker-test` из файлов по 1 ГиБ на всё свободное
  место, потом чтение и сверка. После каждого файла читает выборки по 4 МиБ (новый файл, первый, один из прошлых):
  при потере данных запись останавливается (`stopped_early`), записанное всё равно проверяется. Вызовы по 4 МиБ. Работает поверх
  `trait Volume`; в тестах — имитация носителя (`SimVolume`).
- `probe.rs` — быстрая проверка (как f3probe) поверх `trait Device`; тесты на имитациях подделок (обёртка по 2^k,
  потерянные записи, кэш, сбои в середине, отмена). До первой записи снимает SHA-256 каждого блока 4 КиБ первых
  16 МиБ, последнего 1 МиБ и всех блоков первого прохода (в памяти); не читается блок начала — ничего не пишет.
  Точки делит на `Mismatch` (данные другие) и `IoError` (ошибка чтения / записи), `decide` и правило «перестал
  отвечать» (`Abort::Unresponsive`: первая точка с ошибкой, не читается начало после прохода или после 64 ошибок
  подряд, не читается кусок начала перед записью). После обратной записи — сброс кэша (`Device::flush`) и повторное
  чтение со сверкой (`RestoreCheck`; после 16 ошибок подряд остальное «не читается»; блоки уточняющих проходов —
  `not_reread`). Возвращает `ProbeRun` (результат и счётчики в любом случае); этапы отдаёт колбэком, файлов не трогает.
- `rawdev.rs` — весь носитель: `/dev/rdiskN` / `\\.\PhysicalDriveN`, размер из ioctl, сброс кэша
  (`DKIOCSYNCHRONIZE` / `FlushFileBuffers`); в Windows тома на время проверки блокируются и отключаются
  (`VolumeLocks`).
- `helper.rs` — работа с правами администратора во второй копии программы: macOS — `osascript … with administrator
  privileges`, Windows — `ShellExecuteExW` `runas`. Обмен через файлы в папке задания (`job.json`,
  `progress.json`, `result.json`, `log.jsonl`, `cancel`; папку создаёт окно с правами `0700`). Помощник не пишет через
  ссылки: отказывается от папки-ссылки, каждый свой файл создаёт заново (`create_new_nofollow`), существующий
  `log.jsonl` — отказ. `log.jsonl` (`EventLog`) — по строке на этап (только счётчики, смещения, ФС, очищенный вывод
  инструментов). Ошибка в `result.json` — `error`, `cause` (`privacy|busy|readOnly|gone|denied|unresponsive|
  tooSmall|cancelled|other`), `details`. После быстрой проверки, закрыв устройство и подключив тома обратно, до 10 с
  сверяет разметку (`LayoutAfter`: same / changed / tableGone / driveGone / unreadable). Исправление: `diskutil partitionDisk … MBR <fs> <имя> <байты> FREE gap R`
  (или `eraseDisk` на весь объём) / `diskpart` (`clean`, `convert mbr`, `create partition primary size=…`).
  `UMC_NO_ELEVATE=1` — без запроса прав (для RAM-диска, который принадлежит пользователю).
- `capacity.rs` — что известно о носителе: `Knowledge` (заявленный объём, потеря данных, последняя проверка, последнее
  исправление), `view()` (состояние для окна и план исправления), `check_fix()` (сверка запроса окна), `Store` — файл
  `capacity.json` в папке настроек. Запись ищется по заявленному размеру + разметке разделов (смещение, размер, UUID
  тома в macOS / подпись или GUID диска в Windows), номер `diskN` в ключ не входит; `sync()` держит записи в
  соответствии с подключёнными дисками.
- `report.rs` — отчёт о каждой быстрой и полной проверке и исправлении (JSON, формат 1) в `net::logs_dir()/checks`
  (macOS `~/Library/Logs/UsbMemoryChecker/checks/`, Windows `%LOCALAPPDATA%\UsbMemoryChecker\logs\checks\`): `redact`
  вычищает свободные тексты (пути и метки томов, домашняя папка, имя пользователя, UUID / id таблицы, строки с
  серийными номерами), не больше 32 сбоев и 32 плохих блоков, меньше 256 КиБ, хранится 50 штук не старше 90 дней
  (удаляются только файлы с именем отчёта). Для быстрой проверки собирается из `log.jsonl` и `result.json` помощника
  и решения окна (`main::judge_probe`). Те же отчёты пишет `--cli probe|full|fix` (последняя строка stderr — путь).
- `update.rs`, `donations.rs`, `net.rs`, `settings.rs` — как в 360Cleaner / AdbToolsGUI (в `net.rs` добавлены
  `logs_dir`, `reveal` и `open_privacy_settings` с комментариями по-английски).
  `net::output_timeout` — команда с ограничением по времени (опрос `diskutil` — 10 с, PowerShell — 30 с).

## Важно

- **WebView только в главном потоке**: из потоков — `Ui::send` → `UserEvent::Js`.
- **Быстрая проверка ничего не стирает**: перед каждой записью читает старое содержимое, в конце (и при отмене /
  ошибке) пишет всё обратно в обратном порядке. Не ломай этот порядок — он восстанавливает ячейки, даже когда на
  одну ячейку приходится несколько адресов.
- Помощник с правами перед работой заново находит носитель среди съёмных и сверяет размер (`disks::find`); id
  проверяется `disks::valid_id` (в root-команды попадает только `diskN` / номер).
- Ошибки доступа (`dio::is_access_error`) прерывают проверку, а не считаются «плохими точками»: иначе занятый том
  выглядел бы поддельным.
- Состояние носителя и план исправления считает только Rust (`capacity::view`), окно их лишь показывает и не считает
  размер само. Размер раздела при исправлении — `helper::partition_size` (реальный − 2 МиБ, кратно МиБ), для
  потери данных `capacity::loss_repair_size` (0 → «носитель ничего не хранит», исправление отказывает с `errBroken`).
  Окно присылает `fix {plan, size}`, Rust пересчитывает план и при расхождении отвечает `errRepairChanged`, не запуская
  помощника. `Job.partition` — точный размер в байтах (0 = по `real`); `helper::fix_size` проверяет его до любых
  действий над диском (0, не кратно МиБ, больше диска — отказ). FAT32 — только до 32 ГБ.
- Область полной проверки (`capacity::full_scope`): «весь носитель» только если том не дотягивает до диска не больше
  чем на max(64 МиБ, 2%) и разделы кончаются в пределах 16 МиБ от конца; всё остальное, том в пределах известной
  потери, любой том диска с записью об исправлении и проверка, оборванная ошибкой записи или записавшая заметно
  меньше свободного места (`cutShort`), а также том, где до теста было занято больше max(64 МиБ, 2%) (`nearly_full`:
  мелкая запись заворачивается на ячейки старых файлов), — «раздел проверен» и не «проверен» (`verified`). Таблицу
  разделов, которую не удалось прочитать (`Disk.table_unreadable`: `diskutil info` раздела или `Get-Partition` дали
  сбой; пустой диск без разделов — не сбой), окно показывает как «не подтверждено». Знание, которое не
  подтверждает текущая разметка диска (другой носитель под тем же `diskN`), показывается как «не подтверждено» и
  плана не даёт (`errUnconfirmed`). Задание помощнику несёт `Job.layout` (отпечаток разметки): помощник отказывает,
  если найденный диск устроен иначе. Весь заявленный объём — план по умолчанию только для носителя, признанного настоящим проверкой всего носителя
  (`PlanDefault::Whole`); в остальных случаях он нужен как явный выбор, а помощник отказывает в форматировании на весь
  объём без `Job.whole_confirmed` (его ставит только Rust; `--cli fix` требует размер: пустой или нечисловой — отказ, явный 0 или размер не меньше диска — просьба о всём диске). Ключ записи в `capacity.json` создаёт только наше исправление (`fromRepair`).
- Ручной запуск без вреда настоящим настройкам: `HOME=<папка> target/release/usbmemorychecker` (настройки и
  `capacity.json` лежат под `$HOME/Library/Application Support/UsbMemoryChecker/`, отчёты — под
  `$HOME/Library/Logs/UsbMemoryChecker/checks/`). `UMC_DISKUTIL=<путь>` (только debug-сборка)
  подменяет `/usr/sbin/diskutil` в опросе дисков (проверка ограничения по времени).
- Проверка на RAM-диске: `hdiutil attach -nomount ram://4194304`, `diskutil eraseDisk FAT32 UMCTEST MBR diskN`,
  затем `UMC_SHOW_VIRTUAL=1 UMC_NO_ELEVATE=1 target/release/usbmemorychecker --cli probe diskN`.
  `UMC_DEV_SCRIPT='js'` выполняет скрипт в окне через 2,5 с после запуска (для снимков экрана).
- До v0.1.0 включительно программа называлась UsbMemoryCheker (репозиторий переименован 2026-11-26). Ради
  обновления старых копий: в Windows .zip кладётся тот же .exe ещё и как `UsbMemoryCheker.exe` (старый апдейтер ищет
  его), настройки читаются из старой папки `UsbMemoryCheker`, если новой нет. На Mac старая копия обновится в
  прежнюю папку `UsbMemoryCheker.app`. Убирать это можно, когда v0.1.0 уже не встречается.
- На настоящей Windows программа не проверялась; CI собирает и гоняет там тесты и clippy.

- **Без сохранённой копии не пишем**: блок, старое содержимое которого не прочиталось, не записывается.
- **«Не хранит данные» (Broken) — только из вернувшихся другими данных** первой точки при отвечающем начале. Ошибки
  чтения и записи — не потеря данных: это «носитель перестал отвечать», без вердикта.
- **Недоверенный результат ничего не меняет в знании** (`judge_probe`): «перестал отвечать», неудачная обратная
  запись, несовпавшее или несостоявшееся повторное чтение, разметка не `Same` (а также помощник, умерший после
  снятия эталонов без повторного чтения). Окно получает уведомление `replug`, и `may_start` / `plan_repair`
  отказывают во всех задачах этого носителя (`errReplugFirst`), пока удачный опрос дисков не увидит, что носителя с
  этим `diskN` и размером нет (или до перезапуска). Известная дыра: переподключение быстрее одного опроса (2 с /
  4 с) под тем же `diskN` не замечается. Тексты не утверждают, что совпавшее повторное чтение доказывает, что
  данные лежат во флеш-памяти.
- **Полный доступ к диску** — только macOS и только `EPERM` (`dio::access_cause`); занятый том, защита от записи
  и пропавший носитель получают свои тексты. Кнопка открывает только фиксированную панель настроек (`open_privacy`),
  «Показать отчёт» — только файл, который программа записала сама (`reveal_report` берёт путь из `State.reports`).
- **Отчёты пишет окно (или CLI) от имени пользователя, никогда помощник с правами root.** В них нет содержимого,
  контрольных сумм, меток, путей подключения, UUID, GUID, серийных номеров, имени пользователя и домашней папки.

## Проверки и релиз

- `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, `node scripts/check-i18n.mjs`;
  Windows с Mac: `cargo clippy --all-targets --target x86_64-pc-windows-msvc -- -D warnings`.
- Проверка раскладки окна: `node scripts/ui-check/run.mjs --sizes 1180x760,1600x1000,880x600 --engine both` (WKWebView на Mac +
  headless Chrome/Edge как стенд WebView2; `--states`, `--langs`, `--themes`, `--out <папка PNG>`, `--page <html>`, `--verbose`).
  Для каждого состояния окна (вкладки × состояния ёмкости/задач × диалоги и тосты) × 5 языков × светлая/тёмная тема проверяет:
  страница не прокручивается, прокрутка только внутри списка дисков, таблицы результатов и (в малых окнах) рабочей карточки,
  ни одна кнопка/тик/вердикт не обрезаны, текст не вылезает вбок, у текста с многоточием есть подсказка (это проверка раскладки в
  WKWebView и headless Chrome, не реального WebView2). Ничего не запускает на дисках и ничего не шлёт в Rust (`send` заменён записью
  `__sent`). Выходит с кодом 1 при любой ошибке. Контраст токенов: `node scripts/ui-check/contrast.mjs`; те же клики на старой и
  новой странице: `node scripts/ui-check/ipc.mjs [старый index.html]` (сообщения в Rust должны совпасть); клавиатура и диалоги: `node scripts/ui-check/keys.mjs`. Новый текст/состояние в
  окне — добавь сценарий в `scripts/ui-check/harness.js`.
- Языки: en, ru, es, de, zh (`i18n.rs` `LANGUAGES` = ключи `I18N`). Новый ключ — сразу во все 5 языков. Тексты
  доната — в `usbmemorychecker.json` репозитория DeMoZ/donations и в `assets/donations.json` (держать одинаковыми).
- Релиз: `version` в `Cargo.toml` + `docs/releases/v<версия>.md` (en + ru, их видно в окне обновления) + тег
  `v<версия>` на main. CI выкладывает .dmg, Mac .zip и Windows .zip — **Windows в этом проекте выпускается всегда**
  (так попросил Роман, 2026-11-26).
- Значок: `scripts/make-icon.sh [--sheet <out.png>]` → `assets/`. `scripts/make-icon.swift` рисует каждый размер
  отдельно (никаких уменьшений из 1024): до 48 px — упрощённая геометрия с краями по целым пикселям (мелкие размеры
  подогнаны вручную), от 64 px — с дугой скорости; вариант для Windows (`.ico`) — плитка без отступа, для macOS —
  по сетке значков с отступом. В `icon.ico` размеры до 48 px лежат как DIB, от 64 — PNG. `--sheet` рисует контактный
  лист из упакованных `.ico` / `.icns` (1x на светлом и тёмном фоне) — смотри на него после любой правки. Знак в
  заголовке окна (`index.html`, `.logo`) повторяет 24 px значок: менять вместе. В Windows окно берёт значок из ресурса 1
  в .exe (`build.rs`) в `main.rs`: tao сам его не ставит.
